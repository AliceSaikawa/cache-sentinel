# cache-sentinel 仕様 v0.6 (draft)

v0.4 でモード切り替え(§A〜§C)を、v0.6 で入力禁止の止める対象をユーザーの送信に絞る変更(§1・§3・§5・§8・§9、#7)を入れた。

## A. モード
| モード | 動作 |
|---|---|
| `block`(既定) | 入力禁止(閲覧のみ)。止めるのはユーザーの送信で始まるステップだけ。本書 §1〜§9 |
| `archive` | `idleMinutes` を超えたセッションを自動アーカイブ。[archive-spec.md](archive-spec.md) |
| `both` | `idleMinutes` で入力禁止、さらに `archiveAfterMinutes`(既定 1440 = 24 時間)を超えたらアーカイブ |
| `off` | 何もしない(`/sentinel` と `/unlock` は使える) |

- 実効モード = state.json の `mode`(`/sentinel` で設定)があればそれ、なければ YAML の `mode`。
- 入力禁止のゲートは実効モードが `block` / `both` のときだけ働く(`agent/pre-step` のリスナーは常に登録し、呼ばれるたびにモードを見る)。
- アーカイブのサイクルは実効モードが `archive` / `both` のときだけ働く。
- `/unlock` は実効モードが `block` / `both` 以外なら「入力禁止は無効です(モード: X)」と返す。
- 表示する文面の言語は spec-ui.md §F に従う(ここに書く例は日本語)。

## B. `/sentinel` コマンド
| 入力 | 動作 |
|---|---|
| `/sentinel` | 状態表示: 実効モードとその出どころ(コマンド / YAML)、しきい値、このセッションの最終応答からの経過分、dryRun |
| `/sentinel block` / `archive` / `both` / `off` | 実効モードを変更し、state.json に保存(再起動後も維持)。変更後の状態を表示 |
| `/sentinel default` | state.json の `mode` を消し、YAML の値に戻す |
| それ以外 | エラー: 使い方を表示 |
- 出力の文面は表示言語(spec-ui.md §F)に従う(本書に書く例は日本語)。
- モード変更は即時に反映する(次のステップ・次のサイクルから)。
- `archive` / `both` に初めて変わったとき、state.json に `baselineAt` が無ければ現在時刻を記録する(過去のセッションを一斉にアーカイブしないため)。

## C. 永続状態 (state.json, version 2)
```json
{ "version": 2, "mode": "both", "baselineAt": 1792062384184, "unarchivedAt": { "<sessionId>": 1792064310709 } }
```
- `mode` と `baselineAt` は省略可。version 1(`mode` なし・`baselineAt` 必須)も読める。破損時は空の状態(mode なし・baselineAt なし)。
- 場所: `$DSH_HOME/cache-sentinel/profiles/<プロファイル名>/state.json`(設定 `stateFile` で変更可)。
  - プロファイル名は `ctx.get('profileContext')?.name`(#9、根拠は spike.md「プロファイル名の取得」Z1)。
    プロファイルごとに分けるのは、同じ `$DSH_HOME` を使う複数プロファイルが同時に動いたときに
    モード・`baselineAt`・`unarchivedAt` を後勝ちで上書きし合わないようにするため。
  - `profiles/` の下に置くのは、従来の `state.json` や一時ファイルと同じ階層にしないため(名前が `state.json` の
    プロファイルでも保存できる)。名前は変換しない(spike.md Z3)。
  - 名前が取れないとき(profileContext を provide しないホスト)と、名前が DSH のプロファイル名の規則に合わないとき
    (空、`/` か `\` を含む、`.`、`..`、`node_modules`。DSH の `resolveProfileDir` と同じ。spike.md Z3)は
    従来の `$DSH_HOME/cache-sentinel/state.json`。
  - 移行: プロファイル別の既定の場所を使うとき(`stateFile` を設定していないとき)、起動時にそのファイルが無ければ、
    従来の共有ファイルを読み(無ければ空の状態)、その内容でプロファイル別のファイルを作る。以後の起動では
    従来のファイルを読まない。作れなかったときは warn を出して読んだ内容で動き、次の起動でもう一度移行する。
    ファイルの有無は存在で決め、無いと確かめられたとき(ENOENT)だけ「無い」とする(読めないファイルを上書きしないため)。
  - 従来のファイルは消さない・書き換えない(共有ファイルを使うホストと併存できるようにするため)。
  - `stateFile` を設定しているときは、そのファイルだけを読む(移行しない)。
- アーカイブ状態(DSH の `$DSH_HOME/storages/workspace.json`)は全プロファイルで共有され、
  cache-sentinel からは分離できない。複数プロファイルの同時利用の注意は README の Limitations に書く(§8)。

# 入力禁止(block)の詳細 — v0.6 で止める対象をユーザーの送信に絞った(#7)

## 1. 目的
プロンプトキャッシュが切れた(最後のモデル応答から一定時間が過ぎた)セッションで、
**ユーザーが気づかずに送信して、キャッシュなしの料金で履歴全体を送るのを止める**。セッションは開けて、閲覧もできる。
ユーザーが `/unlock` で明示したときだけ送信を通す。
- 止めるのはユーザーの送信で始まるターンの最初のステップだけ(§3)。エージェントが進めている作業
  (ターン途中のステップ、ジョブ・サブエージェント・ゴール・リマインダーの入力)は止めない。
  止めるとその入力が破棄されて作業が途中で止まり、利用者から理由が分かりにくいため(#7)。
  これらのステップはキャッシュなしで送られることがある(既知のトレードオフ)。

## 2. 用語
- **最終応答時刻 (lastResponseAt)**: そのセッションの最後の `step/end` イベントの `time`(epoch ms)。
  フォークで引き継いだ部分も含めて探す(引き継いだ履歴もキャッシュなしで送られるため)。
  `step/end` が 1 つもなければ undefined(新規セッション)。
  - **サブエージェントの fork の子**(`session.header.origin === 'subagent'` かつ `isSeeded`)だけは扱いが違う(#13)。
    引き継いだ部分の `step/end` は使わず、**子自身が書いた `step/end`** と `header.createdAt` の遅い方を採る
    (`max(子自身の最後の step/end, header.createdAt)`)。子自身の `step/end` が無ければ `header.createdAt`。
    理由: サブエージェントの fork は親のモデル呼び出しの直後(ツール実行中)に起きるので、作成時刻の時点で
    キャッシュは温かい。一方、引き継ぐ最後の `step/end` は「親の 1 つ前のターンの最後のステップ」で、
    親の放置時間の分だけ古くなる(docs/spike.md「サブエージェントの fork の子の判定材料の調査」)。
    2 ターン目以降の子は子自身の `step/end` で判定されるので、挙動は従来どおり。
  - GUI などで古いセッションを fork した場合(`origin` が無い)は上記の例外に当たらず、従来どおり
    引き継いだ部分も含めて探す。
  - fork でない(seed の無い)サブエージェントは従来どおり(`step/end` が無ければ新規として通す)。
  - `header` が無い場合は従来どおり(後方互換)。
- **経過時間** = `now - lastResponseAt`。
- **失効**: 経過時間 > `idleMinutes` 分(既定 60)。

## 3. ゲート (agent/pre-step)
- `ctx.on('agent/pre-step', listener, { prepend: true })` で**最も外側**に登録する。
  自動圧縮(`dsh-compaction-basic`)も同じ waterfall の中でモデルを呼ぶため、それより先に判定する必要がある。
- ステップの種類(`classifyStep`、純粋関数)。payload の `step`(ターン内の番号、1 から)と
  `messages[].source.kind` で決める(根拠は spike.md「止める対象の判定材料の調査」):
  | 種類 | 条件 | 例 | 扱い |
  |---|---|---|---|
  | `user-send` | `step === 1` で、`source.kind === 'user'` の入力を含む | GUI からの送信(queue / steer)、スキルの明示呼び出し(判定に使うのはユーザーの本文。スキル本文は後から足されるので見えない)、GUI からサブエージェントへの直接の送信 | 止める |
  | `mid-turn` | `step >= 2` | ターン途中に入ったジョブ完了通知(inject)やユーザーの steer、ツール実行の後の続き | 通す |
  | `other-input` | `step === 1` で、`'user'` の入力を含まない | ジョブ完了(`tool-jobs`)、サブエージェントの完了(`subagent-settled`)と親からの継続(`agent-message`)、ゴールの自動継続(`goal`)、リマインダー(`schedule`)、webhook、質問への遅い回答(`user-question-reply`)、入力 0 件 | 通す |
  - `mid-turn` は、ターン内で `step/end` の間隔が開いたときの保険。`step/end` はツールの実行が終わり、結果を書いた後に
    追加され、次のステップの pre-step はその直後に走る(spike.md P3)。そのため 2 ステップ目以降は通常 §2 の失効に当たらず、
    `fresh` で通る。長いツール実行の後の続きも同じで、この分岐には来ない(§8)。
  - `user-send` のステップに他の出どころの入力が混ざっていても止める。混ざった入力(ジョブ完了通知など)も一緒に破棄され、
    エージェントには二度と届かない。ユーザー以外の入力だけを受信箱に戻すことはしない。混ざるのはターンの終わりと
    inject が重なったときなどに限られ、稀なため。
  - サブエージェントの最初の課題も `user` だが、新しいセッションか、親の fork の子(作成時刻を基準にする。§2)なので、
    失効の判定で通る。フォークで引き継いだ古い `step/end` では止めない(#13)。
- 判定(`decideGate`、純粋関数):
  1. `lastResponseAt` が undefined → 通す(新規セッション)。
  2. 失効していない → 通す。
  3. ステップの種類が `user-send` でない → 通す。
  4. 有効な解除許可(§4)がある → 通す(許可は消費しない。§4)。
  5. それ以外 → `{ kind: 'reject' }` を返す(`next()` を呼ばない)。
- 拒否の効果(DSH の仕様、spike で確認): リクエストは発生しない。そのステップに入る予定だった入力メッセージは破棄され、
  ターンは `blocked` で終わる。履歴は変わらない。
- `dryRun: true` のときは拒否せず、「拒否するはずだった」ことをログに出して `next()` を呼ぶ。

## 4. 解除 (`/unlock` コマンド)
- `ctx.commands.register({ name: 'unlock', ... })` で登録する。モデルへのメッセージは作らない。
- 実行したセッションに解除許可 `grantedAt = now` を記録する(メモリのみ。再起動で消える)。
- 許可が有効な条件: `now - grantedAt <= unlockTtlMinutes`(既定 10)かつ `lastResponseAt < grantedAt`。
  - 許可後に 1 度でもモデル応答があれば(`lastResponseAt >= grantedAt`)許可は役目を終え、以後は通常判定に戻る。
    応答直後は失効していないので、そのままの会話は自然に続く。
  - 許可後 `unlockTtlMinutes` 以内に送信がなければ失効する(放置中に自動実行が許可を使うのを防ぐ)。
- 応答テキスト(GUI に表示される):
  - 失効中: 「次の送信を許可しました。最終応答から N 分経過しているため、キャッシュなしの料金になります(許可は M 分有効)」
  - 失効していない: 「最終応答から N 分です。キャッシュは有効なのでそのまま送信できます」(許可は記録しない)
  - 応答がまだない: 「このセッションはまだモデル応答がありません」(許可は記録しない)
  - 文面の言語は表示言語(spec-ui.md §F)に従う(ここに書く例は日本語)。
- ブロックされた文面は破棄されているので、ユーザーは解除後に入力し直す。

## 5. ログ
- `[cache-sentinel]` 付きで console と ctx.logger に出す(旧方式で確立)。
- 出すもの: 起動(設定値)、ブロック(セッション id・経過分・ステップ番号)、解除の付与、dryRun の判定、
  失効しているがステップの種類(§3)で通したこと(セッション id・ステップ番号。`other-input` は入力の `source.kind` も)。
- 同じセッションで連続してブロックしてもログは毎回出す(頻度は送信回数分のみ)。
- ログの文面は翻訳しない(日本語のまま。spec-ui.md §F)。

## 6. 設定 (config) — v0.4 で全モード分を統合
| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `mode` | `block`/`archive`/`both`/`off` | `block` | 既定モード(§A) |
| `idleMinutes` | 整数 ≥1 | 60 | 入力禁止のしきい値。`archive` モードではアーカイブのしきい値 |
| `archiveAfterMinutes` | 整数 ≥1 | 1440 | `both` モードのアーカイブのしきい値 |
| `unlockTtlMinutes` | 整数 ≥1 | 10 | `/unlock` の有効時間 |
| `checkIntervalSeconds` | 整数 ≥10 | 60 | アーカイブのチェック間隔 |
| `skipPinned` | boolean | true | ピン留めをアーカイブしない |
| `archiveExisting` | boolean | false | 基準時刻より前に止まったセッションもアーカイブ対象にする |
| `maxPerCycle` | 整数 ≥1 | 20 | 1 サイクルのアーカイブ上限 |
| `dryRun` | boolean | false | 拒否もアーカイブもせずログのみ |
| `stateFile` | string | `$DSH_HOME/cache-sentinel/profiles/<プロファイル名>/state.json` | 永続状態 (§C) |
未知キー・型不正は例外(旧方式と同じ方針)。

## 7. 最終応答時刻の取得
- 初回はそのセッションのイベント(`session.snapshotEvents()`)を末尾から走査して `step/end` を探し、セッション id ごとにキャッシュする。
- 以後は `session/event` リスナーで `step/end` を受けたら更新する。
- 取得に失敗したら通す(安全側=作業を止めない)。ログに warn。

## 8. 非目標 / 既知の制限
- GUI でのバッジ表示・ブロック理由の表示(クライアントプラグインが必要)。ブロックが GUI でどう見えるかは T9 で確認する。
- タイトル自動生成(`session-title-first-prompt-llm`)は最初の送信時に独立してモデルを呼ぶ。新規セッションか
  古いセッションのフォークの初回だけで、送るのは最初のメッセージのみなので対象外とする。
- 自動レビュー(experimental)はゲートを通過したターンの中でしか動かないので対象外。
- サブエージェントのセッションでは GUI から `/unlock` を打てない。親からの継続(`agent-message`)は止めないが、
  GUI からサブエージェントに直接送った入力(`user`)は、サブエージェント側で失効していれば止まる。
- ユーザーの操作でも `user` 以外の出どころで入る入力は止めない(§3)。
  - `/goal <objective>` によるゴールの作成と `/goal edit` による編集、ゴールの再開。ゴールのラウンドは kind `goal` で入る
    (spike.md P2)ので、失効していてもそのまま走る。
  - 添付付きの `/goal`: 添付は kind `user` の別のメッセージとして先に入るので止められて破棄され、その後のゴールのラウンド
    (kind `goal`)は通る。結果として添付なしでゴールが走る(コードを読んだ結果。実機は未確認。spike.md P2)。
  - 質問(`ask_user_question`)への遅い回答(`user-question-reply`)。止めると回答が破棄される。
    質問は回答待ちに戻る(spike.md P2)が、答えたつもりの利用者は答え直しが要ると気づきにくいため、止めない。
- `idleMinutes` を超えるツール実行の後の続きはキャッシュなしで送られるが、プラグインは検出しない。
  キャッシュが最後に使われたのはツール実行の前のモデル応答だが、そのステップの `step/end` はツールが終わった後に
  書かれ、最終応答時刻はそこで新しくなるため(§2 の近似による既存の限界。§3 の `mid-turn`)。ログも出ない。
- キャッシュの実際の寿命はプロバイダとリクエスト内容で決まる。本プラグインは時間だけで判定する近似。
- 対象は `dsh-web-app` バンドルを含むプロファイル(`web`・`desktop`)。`workspaceRegistry` と `connection` を必須で
  inject するので、headless などでは起動しない(#15、根拠は spike.md「対象プロファイルの調査」)。
- **複数プロファイルの同時利用**: `state.json` はプロファイルごとに分かれる(§C)が、アーカイブ状態
  (`$DSH_HOME/storages/workspace.json`)は全プロファイルで共有される。DSH は起動時に 1 回読んで以後再読込せず、
  書き込みでファイル全体を置き換えるため、同時に動かすとアーカイブ / アンアーカイブ / ピンの変更が互いに
  失われうる。これは DSH 側の挙動で cache-sentinel では防げない(根拠は spike.md「プロファイル名の取得」Z4)。

## 9. 受入基準
- B1: 失効したセッションでの送信は拒否され、モデルへのリクエストが発生しない。
- B2: 失効していない・新規セッションは通る。境界(ちょうど idleMinutes)は通す。
- B3: `/unlock` 後の送信は通り、その応答後の会話も通る。
- B4: `/unlock` から `unlockTtlMinutes` を過ぎると許可は無効。
- B5: 許可後に応答があった後、再び失効したら再び拒否される(許可は再利用されない)。
- B6: ゲートは自動圧縮より先に評価される(`prepend`)。
- B7: `dryRun` では拒否しない。
- B8: 最終応答時刻の取得失敗時は通す。
- B9: 設定の検証(§6)。
- B10: ターンの 2 ステップ目以降は、失効していても入力の出どころに関わらず通す。
- B11: ターンの最初のステップでも、`user` の入力を含まなければ(ジョブ・サブエージェント・ゴール・リマインダー・入力 0 件)通す。
- B12: ターンの最初のステップに `user` と他の入力が混ざっていれば止める。
- B13: サブエージェントの fork の子(`origin === 'subagent'` かつ `isSeeded`)の最初のステップは、親から引き継いだ最終応答が
  失効していても通す。子自身の `step/end` が失効していれば止める。子自身の `step/end` が無く、作成から
  `idleMinutes` を超えていれば止める(古い子を再開して GUI から直接送った場合など)。`origin` の無い fork の子は
  従来どおり失効なら止める。
- C1: `/sentinel archive` で入力禁止が止まりアーカイブが始まる。`/sentinel block` で逆。`off` で両方止まる。
- C2: `/sentinel` のモードは再起動後も維持され、`/sentinel default` で YAML に戻る。
- C3: `both` では 60 分で入力禁止、24 時間でアーカイブ。
- C4: 初めてアーカイブが有効になったとき、それ以前に止まっていたセッションはアーカイブされない(`archiveExisting: false`)。
